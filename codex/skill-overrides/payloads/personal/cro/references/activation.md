# Activation and first value

Define the user's first useful outcome and the required setup dependencies. Keep activation separate from registration completion. An activation event should represent experienced value; correlation with retention alone does not prove that forcing the event will improve retention.

Use comparable cohorts and observation windows to examine activation rate, time to value, step drop-off and later retained/qualified behavior. Separate users who have not yet had time to activate from true failures. Inspect affected user journeys before proposing a tour, checklist or extra messages.

## Product experience

Choose a product-first, guided setup or clearly labeled demo route from the product's actual complexity. Show a useful next action and recovery from setup failures. Explain an empty area's purpose and help users add their own content; mark any synthetic examples so they cannot be confused with real saved work.

Use progress indicators and checklists only when meaningful steps exist. Allow users to dismiss optional help, return to incomplete work and avoid repeated tours after completion. Preserve unsaved work and distinguish slow loading from an empty account or failed session.

Define stalled behavior from evidence and normal usage cadence. Improve the in-product recovery path before assuming more communication is needed. Email or human outreach is a separate authorized action; do not create fixed 24/72-hour sequences merely because they appeared in a template.

## Validation

Check first-time, returning, partially completed, interrupted and failed-setup states relevant to the requested change. Verify the intended first-value event and guard against misleading completion metrics, accidental real-world actions in demo mode, and reduced downstream retention or quality.
