# Drafting pages and calls to action

Choose a structure from the actual page purpose, visitor intent, and product evidence. This is a menu, not a mandatory page template.

- Homepage: explain the product and audience, then offer clear paths for visitors with different needs.
- Campaign landing page: match the ad or referral promise and give enough evidence for the next action. Preserve navigation when it serves a real user need.
- Pricing: make current plan differences, limits, billing terms and consequences of a choice understandable. A highlighted plan needs a defensible fit for the stated audience.
- Feature page: connect the capability to a supported use case; show actual behavior or evidence when available.
- About or founder page: preserve the real story and the author's voice. A sales CTA is optional.

A headline should make the page's main meaning clear. Add supporting detail, proof, process explanations or objection handling only where it helps a reader decide. Claims about saved time, outcomes, customer counts or guarantees require real support.

CTA text should describe the action and what happens next. Familiar labels such as “Sign up” are valid when accurate; benefit language is useful only when it improves understanding. Do not imply a free trial, instant result or lack of credit-card requirements without checking.

Use [copy frameworks](copy-frameworks.md) as optional examples. Supply multiple alternatives only when requested or when the user must choose between materially different directions. Metadata belongs in the result only when relevant to the requested surface.
