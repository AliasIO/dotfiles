# Marketing context and connected capabilities

Use the current request and project instructions to locate the authoritative marketing document. Prefer an explicitly named document or a source declared by AGENTS.md/README over a skill’s default filename. For ISO100, reuse `docs/marketing-direction.md` in its project. If no source is declared, check existing marketing/positioning documents before the legacy `.agents/product-marketing.md`, `.claude/product-marketing.md` and `product-marketing-context.md` locations. Do not relocate or duplicate an existing source unless requested.

Read only the sections needed for this task. Ask only when a missing fact changes the result; use a stated assumption for optional detail. Creating a context document is not a prerequisite for normal copy or analysis work. Preserve the distinction between confirmed product behavior, proposals and unverified claims.

For public-facing copy and drafted emails, make the brief [voice and clarity](../copywriting/references/voice-and-clarity.md) check once, preserving facts and intent. It does not require another skill invocation. Do not turn ordinary replies or internal analysis into a marketing-copy task.

Discover relevant connected tools from the current tool catalog. Verify account identity, permissions and data freshness before account-dependent claims. Do not assume a tools registry, CLI file or another skill is installed. Related skills are optional routes: use one when available and relevant; otherwise complete the requested work with existing tools or state the specific missing capability. Do not install services merely to satisfy a cross-reference.

Distinguish advice and drafts from authorized external changes. Carry forward permission already provided, and keep account, campaign, budget, destination and communication scope intact. Keyword/copy approval does not authorize a budget increase or sending a message.
