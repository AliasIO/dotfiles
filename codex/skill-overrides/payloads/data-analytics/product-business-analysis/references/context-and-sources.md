# Context and sources

Use this reference to resolve a specific missing definition, decision, owner, time boundary or source path. A known request with adequate evidence does not need a separate context-gathering stage.

Search with the user-provided product, metric, entity, owner and date anchors. Inspect directly relevant sources first; broaden only when a gap or conflict could change the analysis. Use a targeted query or revised identifier before treating thin search results as evidence of absence. Do not search every enabled source family by default.

Prefer the source that can establish the claim: controlling definitions for metric meaning, current implementation/runtime evidence for shipped behavior, current decision artifacts for approved direction, and executed data queries for actuals. Plans do not prove deployment; informal discussion does not prove consensus. A later explicit owner decision can supersede an older canonical document when its scope is clear.

Retain a compact record of the source, applicable date/window, fact established, and material uncertainty. Reconcile conflicts by authority, freshness, definition, grain, coverage and directness. If unresolved, carry both interpretations and identify the evidence needed to decide.

Stop once the missing context is sufficient for the user's task. Continue to the requested conclusion instead of returning a context note as a substitute. A short sourced context note is the final deliverable only when context or orientation itself was requested.
